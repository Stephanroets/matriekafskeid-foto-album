# Matric Farewell Photo Album

This project is based on the supplied Stefan photo-gallery example, simplified into a private **five-section matric farewell album**.

## Stack

- Next.js App Router
- pnpm
- Vercel hosting
- Supabase Auth (email + password)
- Cloudflare R2 private bucket for photographs
- R2 presigned URLs for direct browser uploads and private image viewing
- Masonry layout + LightGallery viewer from the original example

There is no contact page or contact form.

## The five sections

Edit `lib/album-sections.ts` if you want different names. The starter uses:

1. Arrivals
2. Portraits
3. Friends & Couples
4. Venue & Dinner
5. Dance Floor

Each section maps to an R2 object prefix such as `arrivals/`. Uploading a file to a section makes it appear automatically; the gallery no longer needs hard-coded image arrays.

## 1. Install with pnpm

```bash
pnpm install
pnpm dev
```

The supplied example used pnpm already. The old lockfile was intentionally not copied into this starter because the project now has Supabase and R2 dependencies; `pnpm install` will create a fresh `pnpm-lock.yaml`.

## 2. Create Supabase users

Create a Supabase project and enable Email/Password authentication.

This app deliberately has **no public sign-up screen**. Create/invite the people who may access the album from Supabase Authentication, then give them their email/password.

Add your Supabase Project URL and Publishable Key to `.env.local` using `.env.example` as a guide.

## 3. Create the Cloudflare R2 bucket

Create a private R2 bucket, for example `matric-farewell`.

Create an R2 API token with object read/write access to this bucket. Put the Account ID, Access Key ID, Secret Access Key and bucket name in `.env.local`.

Do **not** expose these R2 credentials with `NEXT_PUBLIC_` variable names.

### R2 CORS

Browser uploads go straight to R2 using a short-lived presigned PUT URL, so R2 must allow your browser origin.

Use `cloudflare-r2-cors.json` as the bucket CORS policy and replace `https://YOUR-PROJECT.vercel.app` with your real production Vercel URL. Keep `http://localhost:3000` for local development.

The bucket can remain private. Gallery reads use one-hour presigned GET URLs.

## 4. Choose who may upload

Set:

```env
ALBUM_ADMIN_EMAILS=your-email@example.com
```

You can allow more than one uploader with commas:

```env
ALBUM_ADMIN_EMAILS=one@example.com,two@example.com
```

All valid Supabase users may view the album. Only addresses in `ALBUM_ADMIN_EMAILS` see/use the upload page.

## 5. Configure Vercel

Import the repository into Vercel and add every variable from `.env.example` under Project → Settings → Environment Variables.

Use the normal build settings for Next.js. The package manager is pnpm; commit the new `pnpm-lock.yaml` generated by `pnpm install` before deploying.

After the first production deployment, make sure the exact Vercel production domain is present in the R2 CORS policy.

## Why uploads bypass Vercel

Photos are often larger than a serverless request-body limit. `/api/uploads/sign` only authenticates the user and returns a short-lived R2 upload URL. The actual photo bytes travel from the browser directly to Cloudflare R2.

## Privacy model

- The website requires a valid Supabase session.
- The R2 bucket stays private.
- Photo links are short-lived presigned GET URLs rather than permanent public bucket links.
- R2 API credentials are available only to server code.
- Upload URLs expire after 10 minutes.

For a family/school album this is substantially better than simply making the R2 bucket public and relying on the login page to hide the links.
